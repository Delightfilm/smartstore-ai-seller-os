# Seller OS 1–5단계 실행 계획 안내

설계 및 실행 계획 승인: 2026-10-13. 상태: **Native 실행 중 — 운영 기반 Task 1, Supabase 로그인 대기**. 본 문서는 구현 완료 보고서가 아니다.

## 순서와 실행 방식

1. [운영 기반](2026-10-13-seller-os-foundation.md): 전용 신규 조직/프로젝트, 실제 로그인, 데이터 권한, 이전 및 백업.
2. [상품 조사 자동화](2026-10-13-seller-os-research.md): SKU 포장 근거, MOQ 검증, 로컬 작업자와 서버 작업 기록.
3. [비용 검증](2026-10-13-seller-os-economics.md): 확인된 비용/가정 구분, 안전한 퀵스타 조회 인터페이스.
4. [심사](2026-10-13-seller-os-review.md): 만료/누락된 근거를 차단하는 서버 판정.
5. [상세페이지](2026-10-13-seller-os-detail.md): 근거와 사용권 기반 생성, 검수 및 준비 자료 내보내기.

실행 방식: 권장한 **Native**로 진행 — 현재 대화에서 주 에이전트가 순서대로 구현하고 테스트하며, 마지막에 독립 리뷰 1회. 사용자가 실행 계획을 승인했으므로 단계마다 동일한 계획 승인을 다시 요청하지 않는다. 외부 비용/로그인/권한/근거 판단 게이트는 유지한다.

## 전 단계 공통 제한

- 기존 DF-AUTOSYNC 조직/프로젝트 쓰기 금지. 신규 전용 조직/프로젝트의 실제 식별자를 확인하고 고정한다.
- 비용 발생 전에 사용자 확인. 카드 입력/유료 전환/과금 리소스 생성/유료 AI 호출을 자동 진행하지 않는다.
- 기존 UI/레이아웃 유지. 실데이터 미연동 지표는 미연동으로 표시한다.
- 등록, 해외 구매/결제, 배송 신청/수정/폐기 API 없음. 네이버 승인 완료도 이번 제한을 자동 해제하지 않는다.
- 사용자 Chrome 세션/로컬 후보 보존. 캡차/로그인 필요 시 해당 창과 상태를 보여주고 자동화 중지.
- 테스트에 맞추려고 상품 사실/견적/사용권을 꾸며내지 않는다. 실제 후보가 통과하지 못하면 보류 결과가 올바른 결과다.
- 작업 브랜치 codex/purchase-agency-pipeline 사용. 커밋/푸시하되 main 병합/배포는 별도 승인.

## 완료 보고 기준

각 단계는 구현, 단위/통합 테스트, 실제 브라우저/서비스 검증 결과를 따로 보고한다. 로그인이 없거나 공급사 API 정보가 모자라면 fixture 성공을 실연동 성공으로 보고하지 않는다. 클라우드 배포와 실제 다른 기기 확인 전 '다기기 운영 완료'라고 표시하지 않는다.

첫 단계 외부 선행 조건: 신규 조직 생성 화면의 로그인, Free 자격/비용 확인, 사용자 소유 운영 계정 확인. 아직 생성 완료된 신규 조직 ID는 없다.
