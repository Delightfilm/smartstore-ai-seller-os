# 해외구매대행 상품 발굴부터 등록까지

## 사용자 요청

1688 탐색 → 국내 경쟁 비교 → 수요/마진 판단 → 한국어 상세페이지 → 스마트스토어 API 등록을 연결한다. 판매 방식은 해외구매대행만이며 재고를 사입하지 않는다. 로그인/보안 인증은 사용자가 열린 브라우저에서 수행한다. 기존 UI와 독립 sourcing-console 경로를 유지한다.

## 실행 방식

### 2026-10-13 실행 범위 변경

사용자가 스토어 심사 미완료 상태에서 나머지 작업을 먼저 진행하도록 요청했다. 이번 구현은 **탐색·비교·검토·상세 초안·등록 준비 파일**까지이며, 아래 원래 등록 설계의 OAuth/이미지 업로드/상품 POST는 보류한다. 준비 파일은 네이버 요청 스키마가 아니며 `PREPARATION_ONLY`로 명시한다. 비용과 단건 공급, 이미지 권리 등이 미확인인 상품은 계속 검토 필요 상태다. API 키 없이 가능한 공개 네이버 브라우저 검색을 대안으로 사용한다. 배송대행 업체는 미정이며 퀵스타/대안의 공개 자료 조사만 허가받았다. 가입·계약·결제·배송 신청을 수행하지 않는다.

사용자가 5단계 연속 진행을 명시적으로 요청했다. 기존 HANDOFF의 자동등록 보류는 이번 작업 범위에 대해 해제한다. 계획과 결과를 문서화하고 현재 사용자 체크아웃의 전용 브랜치에서 직접 구현한다. 기존 수집기 위에 작은 모듈을 연결한다. 별도 클라우드 서비스나 대량 등록 시스템은 만들지 않는다.

## 데이터와 단계

- 1688: 전용 CDP 브라우저의 공개 상품/검색 DOM만 읽는다. 인증 화면이면 해당 탭을 남겨 사용자가 처리하게 한다. 원문 전체/세션은 저장하지 않는다. 상품명, 가격, MOQ, 옵션, 이미지, 공급사의 출처를 보존한다.
- 국내 시장: 네이버 쇼핑 검색 API의 상품 가격/판매처/링크를 수집한다. API가 제공하지 않는 배송비/리뷰는 null. 데이터랩 클릭 추이는 상대 지표로 표시하며 판매량으로 해석하지 않는다. 인증키가 없으면 차단 사유를 표시한다.
- 분석: 주문 단위 원가, 환율, 국내외 운송, 수수료, 반품 충당액과 판매가로 예상 공헌이익을 계산한다. 단건 공급/옵션 매칭/배송비/수요/사용 이미지 권리/판매 가능 여부가 불명확하면 HOLD/REVIEW. 비용 0은 명시적으로 입력했을 때만 인정한다. 검색 결과 건수는 수요가 아니다.
- 상세페이지: 확인된 한국어 이름·설명·사양·선택 옵션·사진과 판매자의 배송/반품 안내로 HTML을 생성한다. 외부 문구는 escape 처리하며 미확인 사양/효능을 만들지 않는다. 초안과 실제 등록 성공을 구분한다.
- 등록: 네이버 공식 OAuth client credentials 및 상품 API. 상품 이미지 업로드 후 네이버 URL을 사용한다. 카테고리/고시정보/원산지/배송·반품/A/S 등은 실제 스토어 설정으로 제공해야 한다. 공급처 확보 가능한 주문 수량은 플랫폼 필드로만 사용하며 보유재고라고 표현하지 않는다. 서버에서 분석 조건을 재검증한다. 등록 결과/중복 방지 상태를 로컬에 저장하고 응답 불명확 시 자동 재등록하지 않는다.

## 보관과 보안

후보와 등록 상태는 Git 제외된 `.seller-os/`에 보관한다. 키는 서버 환경변수 또는 현재 서버 프로세스 메모리에만 보관한다. 브라우저/localStorage/API 응답에 키를 반환하지 않는다. 로컬 변경 API는 같은 origin의 JSON 요청만 허용한다. 원격 이미지 접근은 관찰한 공급처 이미지 CDN의 HTTPS 주소만 허용하고 리다이렉트를 거부한다.

## 완료 기준

각 모듈의 실패/결측/수익 계산/문구 이스케이프/중복 등록 테스트, 빌드, 기존 UI와 실제 5단계 UI 검증. 실계정 키와 상품/비용 정보가 준비됐을 때 한 상품을 API로 등록하고 반환된 상품번호로 확인한다. 외부 준비가 없으면 소프트웨어 구현과 실제 운영 결과를 별도로 기록한다.
