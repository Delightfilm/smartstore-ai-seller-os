# Seller OS 로컬 네이버 커머스 인증·조회

## 현재 범위

현재 PC의 개발 서버만 Naver 인증·계정·채널 조회를 수행한다. 외부 Pages는 운영자가 보고한 마지막 스냅샷을 읽는다. 상품·주문·배송·설정 변경은 구현하지 않는다. 기존 후보 HOLD/NOT_PUBLISHED는 그대로 유지한다.

## 사람이 진행할 설정

1. 네이버 커머스API센터의 운영 스토어 전용 앱을 만든다. 초기 API 그룹은 **판매자정보만** 선택한다. 그룹에는 쓰기 기능도 포함되지만 Seller OS 코드는 고정된 token+두 GET만 호출한다. 나머지 그룹은 추가하지 않는다. 약관·권한·등록은 직접 확인한다.
2. 현재 PC의 실제 outbound 공인 IPv4를 확인해 앱에 등록한다(최대3개). PC IP가 바뀌면 직접 갱신한다. Pages 도메인/DB IP/임시 Edge IP는 사용하지 않는다. 실제 IP를 Git에 기록하지 않는다.
3. 이 저장소의 ignored `.env.local`에 아래 **두 변수만** 직접 입력한다. 기존 VITE 공개 설정은 지우지 않는다. 실제 키·토큰을 채팅, 문서, 스크린샷, Git에 올리지 않는다. 기존 NAVER_CLIENT_ID/SECRET은 Search API용이므로 재사용하지 않는다.

```dotenv
NAVER_COMMERCE_CLIENT_ID=
NAVER_COMMERCE_CLIENT_SECRET=
```

4. 해당 저장소의 Vite 서버만 재시작하고 `http://127.0.0.1:5173/`에 로그인한다. 외부 대시보드에서 키를 입력하거나 로컬 포트를 공개하지 않는다.
5. 설정 → API 키 → 네이버 커머스 API → 인증·조회 확인. 최초에는 반환된 스토어명·채널 번호·HTTPS 주소를 실제 스토어와 비교한 뒤 **이 스토어가 맞습니다**를 누른다. 미확인 결과는 연결 완료로 저장하지 않는다.
6. 저장 성공 후 로컬 새로고침과 외부 Pages 로그인·전체 새로고침에서 같은 채널/revision/시각이 보이는지 확인한다. 외부 버튼은 저장 결과 재조회이며 네이버 재인증이 아니다.

## 상태 해석

- 로컬 비밀 설정 필요: 두 서버 환경변수가 없다. 아직 실인증되지 않았다.
- 최초 스토어 확인 필요: 반환 채널을 직접 대조해야 한다. 결합은 로컬 ignored `.seller-os/commerce-binding.json`에 원자 저장된다.
- 최근 인증·조회 확인: 계정+채널 조회, 수동 결합, 클라우드 저장이 성공한 마지막 결과다. LOCAL_WORKER_REPORTED이며 판매 승인 증명이 아니다.
- 오래된 확인: 마지막 성공15분 경과. 이전 결과/시각은 보존하지만 실시간 정상이라는 뜻이 아니다.
- 최근 시도 실패: IP/인증/권한/호출 제한/응답/채널 불일치를 구분한다. 이전 성공 기록을 최신 정상으로 오인하지 않는다.
- 동기화 미완료: PC가 확인한 결과를 서버에 저장하지 못했다. 외부는 아직 받지 못한 실패를 알 수 없고 마지막 수신 시각만 표시한다.
- 취소/로그아웃/사용자 전환: 새 조회·결합·게시를 막는다. 취소 전에 서버가 이미 commit한 결과까지 되돌렸다고 주장하지 않는다.

## 검증과 운영 경계

`npm test`의 합성 응답 테스트와 실제 네이버 연동 테스트는 별개다. 실키가 없는 상태에서 연결 완료라고 보고하지 않는다. 최소60초 간격, 요청20초/64KiB, 전체45초,401재인증1회,429자동재시도0회다. 수동 재확인만 제공하며 상시 작업/외부 명령 대기열/자동 시작은 없다.

실권한 HTTP 테스트는 명시적으로 제공된 사용자 세션이 있을 때만 실행한다. 브라우저 저장소/네트워크에서 JWT를 추출하지 않는다. DB role/RLS 시뮬레이션은 실제 로그인 HTTP 검증의 대체가 아니다. 테스트용 스냅샷은 트랜잭션 안에서만 만들고 롤백하며 실 연결 결과로 남기지 않는다.

현재 적용·검증 결과와 미완료 항목은 HANDOFF.md의 최신 섹션을 따른다. Edge/Pages는 Git push만으로 배포되지 않는다. 키는 브라우저 번들이나 클라우드 DB에 저장되지 않는다. Supabase service-role key는 기존 Edge 런타임에만 남긴다.

## 롤백

이 PC의 Commerce 어댑터를 중단하고 로컬 비밀 설정을 제거한다. 기존 확인된 Pages/Edge 버전으로 되돌리되 연결 테이블·후보·Auth·다른 앱은 삭제/초기화하지 않는다. 키 폐기/회전은 네이버에서 직접 확인한다. 유료 고정IP/프록시/호스팅이 필요해지면 비용 승인부터 받는다.

## PC로 돌아온 뒤 직접 할 일 — 한 번에 진행

사용자는 현재 외부에 있으므로 지금 로그인·키 작업을 요구하지 않는다. 다음 세 단계만 PC에서 직접 진행하면 된다.

1. **앱 등록 확인:** 열어 둔 네이버 커머스API센터에서 전용 앱 이름·설명과 대상 스토어를 확인한다. 그때의 현재 PC 공인 IPv4를 다시 확인해 등록하고 API 그룹은 판매자정보만 추가한다. 다른 그룹은 추가하지 않는다. 최종 권한·확인·등록은 직접 제출한다. 아직 등록하지 않았다면 이때 진행하고 이미 등록했다면 중복 앱을 만들지 않는다.
2. **로컬 비밀값 입력:** 저장소 `.env.local`의 빈 NAVER_COMMERCE_CLIENT_ID/SECRET 두 줄에 발급값을 직접 넣고 저장한다. 기존 공개 환경설정을 지우지 않는다. 파일은 Git무시이며 채팅·스크린샷으로 공유하지 않는다. 저장 완료 여부만 알려주면 서버 재시작 및 실제 연결 검증을 이어간다.
3. **최초 스토어 대조:** 로컬 Seller OS에 필요 시 로그인하고 설정 → API 키에서 조회 결과의 이름·채널 번호·주소가 실제 운영 스토어와 같은지 확인한다. 맞을 때만 최초 확인을 누른다. 외부 Pages도 로그인이 풀렸을 때만 직접 로그인한다. 그 뒤 실제 저장/조회/전체 새로고침 검증은 에이전트가 진행한다.

현재 IP는 PC 네트워크 변경 시 달라질 수 있으므로 이 문서에 고정하지 않는다. 새 호스팅, 결제, 상품 등록, 배송 신청은 필요하지 않다.

## 이번 구현에서 내린 판단과 남은 위험

- 지정된 기존 체크아웃/작업 브랜치를 재사용했다. 별도 worktree보다 격리가 약하므로 clean baseline·파일별 staging으로 범위를 제한했다.
- Windows에서 보조 Bash 기록 스크립트가 실패하여 ignored 수동 ledger를 사용했다. 진행 기록 자동화 대신 수동 기록 오류 가능성이 남는다.
- 최초 동시 저장은 transaction advisory lock으로 직렬화했다. 기존 workspace에 UPDATE 권한을 더하지 않으며 hash 충돌은 불필요한 직렬화만 초래한다.
- 공유 DB/Edge 적용은 독립 코드 리뷰와4건 수정 뒤에 진행했다. 배포 순서가 분리되어 버전별 검증이 필요했고 실제15파일 manifest를 대조했다.
- 실제 네이버 앱/키/IP/API 응답 호환성은 사람 참여 검증 전이다. 단위 테스트를 실연결 완료로 해석하면 안 된다.
- DB role/RLS/CAS는 rollback-only 실제 SQL로 검증했지만 별도 사용자 JWT를 사용하는 일부 HTTP 권한 검증은 미완료다. 인증 없는 HTTP 거절과 실제 로그인한 UI의 빈 스냅샷 조회는 확인했다.
- 외부 Pages 배포·로그인 유지·새로고침·미검증 상태는 확인했으나 실 연결 결과 표시는 아직 검증 전이다. 외부 local fetch0은 클라이언트 경계 테스트로 검증했으며 실제 네트워크 캡처 검증과 혼동하지 않는다.
- React 브라우저는 현재 미설정/미검증 상태만 실제 확인했다. 최초 확인·실패·동기화 상태는 합성 테스트로 검증했으며 실키 상태 검증은 남았다.
- 기존8개 dependency audit 및 다른 앱/Auth advisory는 변경하지 않았다. 기존 취약점 위험이 남으므로 별도 승인 범위에서 검토해야 한다. 관련 Supabase 조치 안내: [공개 SECURITY DEFINER 실행 경고](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [유출 비밀번호 보호](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- 공인 IP 변동/PC 꺼짐은 로컬 무료 구조의 제약이다. 자동 무중단이나 고정 IP를 보장하지 않는다.
